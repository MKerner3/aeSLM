# AE Fine-tuned Small language model (SLM)
This repository contains all necessary files/scripts used to clean and process JSON data used to train the phi-3 language model, and also contains python scripts that use a language model (in the form of a .gguf file) to generate responses for varying user input.

# Model Performance Summary

  The AE 2010/11 Small language model is a fine-tuned version of Microsoft’s Phi3 small language model that has been trained to solve thermodynamics and fluid mechanics problems specific to Georgia Tech’s AE 2010/11 course. The baseline model has 3.8 billion parameters with output generation comparable in quality to much larger language models, making the default model robust and lightweight on its own. The model performs well in metrics such as language understanding, common sense, factual knowledge, math and code generation. However, the model can be further improved for specific use cases, which is the goal of the AE 2010/11 small language model. By training Phi3 with 801 student-created problems in thermodynamics and fluid mechanics, the AE 2010/11 language model is tailored to solve problems that appear often in the course. While its performance has not been assessed in complete entirety, early tests suggest that the model performs quite well in conceptual reasoning, but sometimes may hallucinate when asked to solve multi-step problems necessitating physical understanding and mathematical logic.
  
  On a conceptual level, the model performs well and answers inquiries with good accuracy, often providing detailed responses that exhibit a good level of understanding on course material. The answers can sometimes be verbose, but almost always directly answers the question that a user inputs. Additionally, the model is able to demonstrate an idea of describing how to use equations to model systems and achieve desired outputs. For example, the model can recognize parts of an equation that are steady state terms or terms that depend on viscosity or external forces. It is in this area (conceptual understanding) that the model performs the best and can help a student/user gain a fundamental understanding of course concepts before tackling more mathematically involved problems. This makes sense because many of the training problems used for the model were conceptual questions that had short-response answer outputs.
  
  When asked to solve complex, multi-step problems requiring algebraic manipulation and applied knowledge of course concepts, the language model can struggle providing correct answers. Often, the model will make a mathematical error such as an incorrect calculation or error in an answer's magnitude, or will hallucinate assumptions in the problem that lead to an incorrect answer output. Sometimes, the model can provide incorrect equations that have either missing terms or have extra hallucinated terms making the equation wrong. This typically happens with explicit equations such as normal shock relation equations, but will be more reliable with more generalized equations (such as steady flow momentum). This allows for the model to generate correct responses fairly frequently for simple to intermediate level fluid mechanics and thermodynamics questions. The language model can often provide the correct python code to perform these calculations, but will also have issues when tasked to write scripts for complex questions. When incorrect responses do occur, regenerating a response will generate a different output that can sometimes be more accurate than the initial response.
  
  While more work is needed to quantitatively determine the accuracy and quality of the language model’s output generation, the model shows promise of being a unique tool to help students learn thermodynamics and fluid mechanics better. With more custom training data that can be created by professors and external python scripts to autocorrect small math errors, the AE 2010/11 language model can be further improved and further facilitate learning.

## Overview and Usage of Post processing scripts
While it may be easy to simply run the language model through a terminal using Ollama or through docker desktop + openwebUI, one particular problem that arises is the inability of the language model to accurately calculate mathematical expressions. (This is an inherent problem with many language models.) To effectively resolve this issue, python scripts such as process_math.py in this repository can be used which allow a user to interact with a language model, but will intercept the language model's response in a string and verify mathematical operations inside of it to ensure accurate responses. As of this commit, the python script corrects simple mathematical calculations but future commits may see the wolfram API being used to verify the accuracy of more complex math.

The process_math.py file is currently still being developed, so running it as of the current commit may not produce desired results at this time.
